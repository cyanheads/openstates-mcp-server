# 0.2.2 — 2026-07-31

## Added

- **`openstates_search_people`** takes `id` — an array of OCD person IDs, sent upstream as repeated `id=` parameters — so a person ID returned by a bill's sponsorships, a committee's memberships, or a prior search can be fetched back directly. `jurisdiction` becomes required-unless-`id` via a schema-level `.refine()`: a call passing `jurisdiction` alone is unchanged, and a call carrying neither field is rejected as an input-validation error. JSON Schema `required` cannot express an either/or, so the constraint is stated in the tool and field descriptions instead — the same pattern `openstates_search_bills` already uses for `jurisdiction`-or-`q`. ([#42](https://github.com/cyanheads/openstates-mcp-server/issues/42))

## Changed

- **`openstates_get_bill`, `openstates_get_committee`, `openstates_search_bills`, `openstates_search_committees`** — the person ID fields on sponsorships and committee memberships now point to `openstates_search_people`'s new `id` lookup for the full record. ([#42](https://github.com/cyanheads/openstates-mcp-server/issues/42))

## Fixed

- **Every tool returning bill, session, person, committee, or event data** — output fields Open States can send as `""` now document that in their own `.describe()`, so a `structuredContent` consumer can tell "not recorded" from a malformed record. No field's type, optionality, or nullability changed. Covers bill dates and notes, legislative session `classification`/`start_date`/`end_date`, person name and profile fields, committee-membership fields, and the `note` field shared by links, sources, media, and document records across tools. ([#44](https://github.com/cyanheads/openstates-mcp-server/issues/44))
