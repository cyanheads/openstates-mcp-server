# 0.2.0 — 2026-07-31

## Changed

- **Breaking:** `jurisdiction` is now `z.string().min(1)` — a required input schema field — on `openstates_search_people`, `openstates_search_committees`, and `openstates_search_events`. Previously the field was schema-optional and the requirement lived only in a handler guard, so `tools/list` advertised `required: []` even though every omitted call was rejected. A call that omits `jurisdiction` now fails schema validation instead of reaching the handler; the `jurisdiction_required` error contract (and its `data.reason`/recovery hint) is gone from all three tools, since the guard it backed is unreachable. Discovery guidance that lived in the recovery hint now lives in each tool's description, reached the same way via `tools/list`. `openstates_search_bills` is unchanged — its `jurisdiction`-or-`q` rule is a genuine either/or that JSON Schema `required` cannot express, so its handler-level `missing_scope` check stays. ([#35](https://github.com/cyanheads/openstates-mcp-server/issues/35))

## Added

- **`openstates_get_legislators_by_location`** discloses the federal delegation `/people.geo` already returned alongside state legislators: `jurisdiction.classification` (`"state"` vs `"country"`) on every legislator, `stateCount`/`federalCount` in the enrichment, and a per-legislator tier label plus a header split in the rendered text. `given_name` and `family_name` are added to the output schema, matching `openstates_search_people`. ([#36](https://github.com/cyanheads/openstates-mcp-server/issues/36))
- **`openstates_search_bills`** `appliedFilters` now echoes `subject`, `sponsor`, and `sponsor_classification` in addition to the filters it already carried, and the zero-result notice is built from the same record so it can no longer disagree with the echo — every filter that narrowed the query, not just the first four, is named. An unrecognized `jurisdiction` is called out by name against the covered inventory rather than folded into a generic "broaden the query" hint, since Open States answers one with HTTP 200 and zero rows. ([#32](https://github.com/cyanheads/openstates-mcp-server/issues/32))

## Fixed

- **`openstates_get_bill`, `openstates_search_bills`** — `other_identifiers[].scheme` is now optional in both output schemas, matching every bill record Open States returns. Previously any call with `include=other_identifiers` failed the output parse outright and lost the whole bill, because upstream omits `scheme` on bill identifiers unconditionally. The renderer no longer prints an empty `(undefined)` when `scheme` is absent. `openstates_search_people` and `openstates_get_legislators_by_location` are unchanged — upstream does supply `scheme` for the person entity. ([#31](https://github.com/cyanheads/openstates-mcp-server/issues/31))
