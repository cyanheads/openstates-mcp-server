# 0.3.3 — 2026-10-08

## Added

- **Argument repair** — a numeric string sent for a number field (`per_page: "5"` on `openstates_search_bills`) and a lone string sent for an array field (`include: "legislative_sessions"` on `openstates_get_jurisdiction`) are accepted (mcp-ts-core 0.13.14). A `null` at an optional key is treated as absent (0.13.14), and JSON-stringified objects and integers sent for string fields are repaired (0.13.9).
- **Request id on errors** — tool error results carry `data.requestId`, and the text closes with `request <id>` (mcp-ts-core 0.13.10).
- **Telemetry and logging env vars** — `.env.example` and the README document `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT`, `LOG_TOOL_FAILURE_PAYLOADS`, and `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES` (opt-ins added in mcp-ts-core 0.13.8).
- **`.mcpbignore`** excludes `docs/idea.md`, `logs/`, `.cache/`, `coverage/`, and `tests/` from the `.mcpb` bundle.

## Changed

- **Argument rejections** name the field path and give a typed hint (`jurisdiction: true` → "Send jurisdiction as a string, not a boolean.") (mcp-ts-core 0.13.9); the `-32602` rejection is bounded in size (0.13.14). The advertised tool, resource-template, and prompt schemas are unchanged.
- **Recovery hints** for `not_found`, `invalid_page`, `missing_lookup_params`, `invalid_coordinate`, and `upstream_timeout` are no longer forwarded by hand with `ctx.recoveryFor`; the framework fills the declared hint (mcp-ts-core 0.13.10). The text on the wire is unchanged.
- **`server.json`** npm entries use `"runtimeHint": "npx"` with no package arguments (previously `bun` with `run start:stdio` / `run start:http`), and the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `http` (mcp-ts-core 0.13.11), so registry clients launch it over HTTP.
- **Docker image** installs production dependencies in a `deps` stage on `$BUILDPLATFORM` that cross-installs for the target (mcp-ts-core 0.13.10) and prunes musl-only packages (0.13.11), via the new `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts`. The image creates writable `.cache` and `.mirror` directories for the runtime user, and no longer sets `MCP_FORCE_CONSOLE_LOGGING`.
- **OpenTelemetry** — `OTEL_EXPORTER_OTLP_ENDPOINT` alone now exports traces and metrics, and nothing exports when no endpoint is set (mcp-ts-core 0.13.7).
- **`package.json`** — `start`, `start:stdio`, and `start:http` run on `node dist/index.js`; `test` is `vitest run`; `audit:fix` is added; `files` excludes `dist/*.mcpb` from the npm tarball.
- **Ignore files** — `.gitignore` and `.dockerignore` cover every `.env*` file and the MCP Registry token files, keeping `.env.example` tracked.
- **CodeQL workflow** runs one job per language (`actions`, `javascript-typescript`) and uploads each under `/language:<language>`.
- **Tests** for the refactored handlers move to `runToolContract` and `createWorkerHandler`; `scope-enforcement` sends booleans for its wrong-type shapes because the framework now repairs integers and lone strings.
- **Docs and tooling** — `CLAUDE.md`, the README badges (Bun 1.4.2, MCP SDK ^2.2.0), the resynced `framework-skills/`, and the devcheck, lint, and release scripts match mcp-ts-core 0.13.14.
